Group independent read-only file inspections and searches into one bounded bash call instead of one model round per file or command.
Label each result so failures and source files remain distinguishable. Limit output to the relevant sections and read saved output when needed.
Keep writes, dependent actions and commands that need separate failure analysis sequential. Do not launch background work that can outlive the turn.
For tests, use the smallest meaningful check set for the identified risks; combine independent checks only when their individual exit codes and logs are preserved.
Batching is an execution choice, not permission to skip evidence, change scope, repeat writes or claim unexecuted checks.
The bash command limit is 4000 characters. For a longer script use write_file and execute the saved file with a short bash command. Do not retry an oversized inline command.
For SonarQube Cloud PR analysis, read /api/project_pull_requests/list?project=<project-key>, select the requested PR and compare commit.sha and analysisDate with the verified PR head before accepting PR-scoped measures. /api/project_analyses/search can return main-branch analyses despite a pullRequest parameter; absence of the PR SHA there does not prove the PR analysis is missing. Keep the metric, analysis revision and observation time together. Add the remaining behavioral tests as one coherent correction, measure the local coverage gap and then publish a verified revision; do not spend a CI cycle per uncovered branch.
Use the supplied runtime command inventory before choosing commands. Prefer configured GitHub MCP tools over requiring gh. Read repository dependency groups and CI configuration before installing or running checks; unavailable local services can be verified through matching CI receipts, not reported as locally executed. Before declaring a service missing, inspect CI services, test guards, opt-in environment flags and dependency setup at the exact revision. A missing local executable does not prove the service is absent from CI. When it is already configured, add the missing behavioral tests and use the configured test path; do not ask to add that service again or call the target impossible. An isolated test instance of an existing project service is not a new external service or a production infrastructure change; honor any explicit setup restrictions. Fetch does not authenticate private GitHub API calls: CodeQL alert listing requires an authorized API request and security_events=read. On HTTP 401/403, identify the missing authentication/permission, return a concrete blocker and stop retrying the same inaccessible operation. Confirmed missing permissions, worker capacity or service prerequisites require a blocked result, not repeated partial reports with unchanged prerequisites. Keep successful evidence and the exact revision available to the parent.
For roles allowed to publish PRs, the runtime supplies the repository owner's Git author and committer identity through GIT_AUTHOR_NAME, GIT_AUTHOR_EMAIL, GIT_COMMITTER_NAME and GIT_COMMITTER_EMAIL. Preserve these variables and never substitute an agent identity or override them with --author. For an authorized amend that must use the owner's identity, use --reset-author. Identify agent assistance only in an Assisted-by trailer. Before publishing, verify both author and committer against the supplied identity; report any mismatch instead of silently publishing it. Do not rewrite existing remote history without authorization.
