Before testing, choose checks from repository requirements and changed behavior. Tie each new check to a required check or an unresolved risk; a full suite is appropriate when required or when that risk spans modules.
Keep a verification record in checkpoint decisions: exact command, working directory, verified revision, relevant environment, exit status, test counts including skips, and the saved output path. Reference these receipts in the final report.
Read saved output with read_tool_output (or read_file for a log you redirected yourself) to inspect failures. Do not rerun a suite to recover output or list failed tests. Avoid piping test commands through tail/head: this discards evidence and may hide the test exit code; the Bash tool already saves full stdout/stderr.
Rerun checks only for changed source, environment or invocation, an incomplete run, an explicit reproducibility question, or a required validation step. State that reason and reuse unaffected results. After a broad run fails, inspect the saved log and select the smallest failing subset for diagnosis instead of repeating the full suite.
Compare head/base test IDs and failure causes, using the same invocation and environment at verified revisions. The same failure counts or unchanged test files alone do not prove failures are pre-existing. If equivalence is not established, report it as unverified.
Diagnose the first causal error before classifying a failure. For a missing dependency, inspect project setup and use available tools to install it inside the sandbox when permissions and budget allow; rerun the affected check. If installation is unavailable, state the exact limitation. An environment failure is not a passing test.
Once required checks and identified risks are covered, record remaining_work=[] and finalize. Do not add an optional broad pass merely because time remains or no new findings were found. Keep unresolved failures and publication requirements explicit.
